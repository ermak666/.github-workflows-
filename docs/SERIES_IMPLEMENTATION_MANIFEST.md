# Производственный манифест серии «Разработка без страха»

## Обещание серии

Каждый учебник выпускается как **отдельное Android-приложение** с собственным названием, иконкой, локальными уроками, прогрессом и APK. Все приложения используют одну проверенную учебную стратегию, но не делят пользовательские данные между собой без явного запроса пользователя.

## Единый критерий готовности приложения

| Область | Обязательный минимум |
| --- | --- |
| Учебная программа | Последовательные уровни **Junior → Middle → Senior → Проекты и практика**; объём уроков определяется сложностью предмета, а каждый уровень имеет проверку освоения. |
| Урок | Простая русская аналогия, цель, нужные для понимания примеры и практика с подсказкой и разбором. |
| Практика | Достаточно разнообразных задач для реального закрепления темы, безопасная проверка результата либо честная проверка формата/логики. |
| Справка | Шпаргалки по действительно нужным темам приложения, поиск и короткие примеры. |
| Прогресс | Офлайн-сохранение, история, повторение после перерыва, недельный блиц и цели. |
| Доступность | Единственная тёмная тема, высокий контраст, масштаб текста, снижение движения, понятная навигация. |
| Качество | TypeScript, линтер, тесты, production-сборка, ручной список проверки на телефоне. |
| Выпуск | Отдельный GitHub-репозиторий, workflow Android APK, checkpoint и скачиваемая APK. |

## Общая архитектура

В каждом репозитории будут одинаковые слои: `shared/course-content.json`, `shared/practice-challenges.ts`, `shared/cheat-sheets.ts`, локальное хранилище прогресса, экран урока, тренажёр, шпаргалка, отчёт и настройки. Общий каркас будет храниться отдельно, а предметный контент — в данных конкретного приложения.

Для запуска кода используются только предметно безопасные форматы. Например, JavaScript-учебник будет иметь ограниченный учебный запуск JavaScript, SQL-учебник — безопасную in-memory песочницу SQL, а Git/Linux/Docker — симулятор команд с предсказуемыми состояниями. Никакой учебник не будет выполнять произвольные системные команды, обращаться к локальным файлам пользователя или сети без отдельного безопасного механизма.
